# BREAKFRONT 账号认证系统 — 架构设计（2026-09-05）

> 状态：设计稿（v0.1）｜ 触发：多人正式化时需要"第三方 MC 认证登录、可定制化登录体验"
> 关联：离线服（online-mode=false）场景、公测服 mc.geekhonize.top、client 自研 UI 体系

## 1. 要解决的问题

当前服务器为**离线模式**（不验证 Mojang），任何同名玩家都能冒名登录；且登录完全走原版，
无法定制登录体验、无法做账号权益（白名单/管理员/徽章）。多人正式化后必须有「BF 自有认证」：

1. **防冒名**：玩家身份由服务器信任的账号体系锚定，而非客户端自报名字。
2. **定制登录**：BF 自研登录/注册界面（替换原版登录屏），为后续「个性化登录」（皮肤/成就/权益）打底。
3. **多人可达**：支持海量玩家注册/登录/会话续期，随时可扩。

## 2. 边界与前提

- 仍以**离线服 + 应用层认证**为主路线（不引入 Mojang 正版验证流程依赖）。
- 认证发生点在**连接服务器之前**（客户端）与服务端**握手阶段**（服务端），不污染对局玩法层。
- 不绑定任何具体云账号；预留 OAuth 适配点（后续可对接自建/微信/QQ 等第三方 OAuth）。

## 3. 顶层流程

```
[客户端 BF 登录屏]                 [服务端 BF Account Service]
   输入 账号+密码 / 注册
        │ C2S AuthLoginPayload(account, secretHash)
        ▼
                             校验账号库(runDir/breakfront/accounts.json)
                             生成会话令牌 token=rand(32B)
                             下发 S2C AuthResultPayload(token, displayName)
        ▼
   记录本地会话(credentials/session.dat)
        │ 后续进服（同一 JVM / 重启后带 token）
        ▼ ServerHandshake/登录包携带 token
                             服务端握手校验 token → 分配 BF 玩家身份
                             （名字以账号 displayName 为准，防冒名）
```

- **令牌生命周期**：登录会话 12h 可续；服务端重启清空在线会话，玩家重登。
- **注册门槛**：可配置（开放注册 / 邀请码 / 仅管理员建号），默认邀请码=管理员密码串（admin 建号）。

## 4. 服务端组件（core 新增 `server.auth`）

| 组件 | 职责 |
|---|---|
| `AccountStore` | 账号持久化（runDir/breakfront/accounts.json 或 SQLite 后续）；密码仅存 **scrypt/salt 哈希**；字段 {uuid 固定派生, account, displayName, salt, hash, roles[], createdAt} |
| `AuthService` | 注册/登录/令牌签发与校验（token → Account 会话表，超时回收）；`allows(player)=admin||auth 会话||op` 决策点已存在的 AdminService 与会话机制对接 |
| `AuthNet` | C2S AuthLoginPayload / S2C AuthResultPayload 注册（复用 core net 体系） |
| 握手校验 | ServerPlayConnectionEvents.JOIN 前校验 token（客户端在进入前已带凭据） |

角色（roles）：`player` / `vip` / `admin` / `builder`。管理员登录仍走原 AdminService 密码会话；
auth 账号若 roles 含 admin 则允许直接执行管理指令（与 /bf admin 双轨兼容）。

## 5. 客户端组件（client 新增 `ui.auth` + `state.AuthState`）

| 组件 | 职责 |
|---|---|
| `BreakfrontLoginScreen` | BF 风格登录/注册全屏页：账号、密码、显示名（注册时）、状态徽章；矢量几何、无贴图（与全 UI 体系一致） |
| `AuthState` | 本地会话（token/displayName）内存 + 落盘（.minecraft 下 credentials/bf-session.dat，chmod 仅本账号）；`isLoggedIn()` 供主菜单/部署判断 |
| `AuthNet` | C2S/S2C payload 收发（与 core 同名桩，客户端侧） |
| 登录 UI 出口 | 主菜单新增「登录」区/首次进服前置；「管理」与认证解耦：管理=admin 密码；玩家=账号登录 |

**定制化点**：LoginScreen 按钮与视觉全部走 BfTheme/BfDraw 体系；未来换第三方 OAuth 只需替换
「登录框 → 跳授权」一步，账户会话层不动。

## 6. 安全清单（实现时必须满足）

1. 密码永不明文落盘/网络传输（客户端 SHA-256 预哈希一次防意外日志泄漏 + 服务端 scrypt）。
2. 令牌 32B 随机、服务端仅存哈希；会话表带过期；登录失败限速（每账号 5 次/分钟）。
3. displayName 白名单字符 `[A-Za-z0-9_\u4e00-\u9fa5]{2,16}`，防聊天/名字注入。
4. 不信任客户端自报 UUID：账号 UUID = 服务端固定派生（account 名 sha 前缀 v4 规范），换名不换号。
5. 纯离线可玩性保留：无服务时主菜单提供「离线浏览」降级（只读模式，不进服）。

## 7. 里程碑（实现批次）

- M1：AccountStore + AuthService 纯 Java 单测（注册/登录/错误/限速）→ /bf auth register|login|logout 指令
- M2：网络链路（C2S/S2C payload、core+client 桩与 exclude）+ AuthState 本地会话
- M3：BreakfrontLoginScreen（BF 视觉）+ 主菜单登录区 + 进服鉴权钩子
- M4：握手校验（JOIN 前置校验 token、防同名冒名）、roles→管理双轨
- M5：可选第三方 OAuth 适配（预留接口，遇真实第三方再定）

## 8. 影响面 / 兼容

- 不改变对局玩法协议；新增 payload 与 core/client 共享类型规则沿用既有（仅 core 发，client 桩+exclude）。
- 旧存档/玩家：首次登录自动以其名字建号（把存量账号接上），后续强制认证。
- 公测阶段建议默认"开放注册"；公网正式开放前切换"仅管理员建号"。
