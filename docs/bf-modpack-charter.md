## 0. 一句话定位

在 Minecraft 1.21.1（Fabric）中，复刻「战地」系列核心体验的 **32v32 大战场整合包**：现代枪械 + 坦克/直升机载具 + **攻防模式（Breakthrough）**回合玩法，客户端 + 服务端成套交付，首发目标为**攻防模式**，后续按路线扩展玩法模式。

### 已确认决策（与用户对齐）

| 维度 | 决策 | 备注 |
|---|---|---|
| MC 版本 | **1.21.1（Fabric）** | 生态完整性的现实选择，见 §2 兼容矩阵 |
| 渲染/性能 | **VulkanMod** 为客户端首选渲染器 | 1.21–1.21.1 有对应构建；有 OpenGL 兼容红线 |
| 战场规模 | **32v32（64 人）** | 决定地图尺寸、服务器规格、性能方案 |
| 首发模式 | **攻防 Breakthrough** | 攻方推线拔点 vs 守方拖时耗票 |
| 首发图主题 | **城市街区攻防** | 视觉与动线参考三角洲行动「攀升」，沿街区纵深推进 |
| 武器体系 | **TaCZ（Refabricated）+ 枪包** | Fabric 1.21.1 可用；与 656 系（Killicon/FrontVoice/LightCore）联动潜力大 |

| 界面方向 | **BF2042 风格全界面，矢量绘制（非像素化）** | 完整规格见 §4.7 |
| 后续模式池 | 征服 Conquest、三角洲行动「胜者为王」类模式 | v2 再调研立项 |

## 1. 项目目标与范围

### 1.1 体验目标（按优先级）

1. **攻防对局能完整、稳定地打满一整场**（64 人不掉链子）—— 第一优先级。
2. **载具与步兵协同**：坦克推进、直升机机降拔点，步兵反载具手段闭环。
3. **"战地味"氛围**：部署动画/倒计时、击杀播报、比分与扇区进度条、战场音效、近距语音。
4. **地图是作品不是场地**：首图达到"值得反复打"的建筑密度与攻防节奏设计。
5. 破坏感与复原：可炸建筑 + 关键结构受保护 + 每局结束战场复原。
6. **全界面体验对齐 BF2042**：部署/兵种/计分/结算等完整界面与交互逻辑，**矢量绘制不像素化**（§4.7）。

### 1.2 非目标（本期明确不做）

- 不做生存/经济/合成管线（枪与载具由规则层直接发放，不经生存合成）。
- 不做自定义物理引擎或新维度生成算法。
- 不自研枪械/载具本体——枪械用 TaCZ、载具用 SBW（§3.1）。
- 不做跨服（Proxy/分片）网络；单服承载 64 人。
- Bedrock/网易版不在范围。

### 1.3 交付物清单

- **整合包**（客户端侧：安装器/模组清单 + 客户端资源与配置）
- **服务端套件**（含所有服务端模组、世界模板、地图资产、一键启动脚本）
- **自研模组源码**：`breakfront` 仓库（服务端权威逻辑 + 客户端 HUD 双入口）
- **地图工作流**：从 WorldEdit 构建到竞技场打包、局末回滚的完整工具链
- **部署与运维文档**：服务器规格、开服、平衡调参、备份

## 2. 技术底座与版本决策

### 2.1 为什么是 1.21.1 而不是 1.21.11

1.21.11（Mounts of Mayhem）的渲染与性能生态完整（VulkanMod 0.6.1、Lithium/VMP/C2ME 全家桶齐全），
但**战地内容模组全部停在 1.21.1**。核心结论：没有第三方内容模组，整合包 P0 无法成立。

| 关键模组 | 1.21.11 | 1.21.1 |
|---|---|---|
| Superb Warfare ReFabricated（枪械+载具） | ✗ | ✅ 0.8.8-alfa，2026-08 仍高频更新 |
| TaCZ 永恒枪械 ReFabricated | ✗ | ✅ 1.21.1 / 1.20.1 |
| Vic's Point Blank（Fabric） | ✗ 未跟进 | ✅ 1.21.1 系 |
| VulkanMod | ✅ 0.6.1 | ✅ 1.21–1.21.1 构建 |
| Lithium / Krypton / FerriteCore / Spark | ✅ | ✅ |
| Very Many Players (VMP) | ✅ | 待实机验证 |

**工程策略：按跨版本可升级结构搭。** 版本号集中在 `gradle.properties`，业务代码避免直接依赖第三方模组类（通过我们自己的桥接层隔离），未来 TaCZ:Refabricated / SBW ReFabricated 跟进 1.21.11/26.x 后整体抬升版本。

### 2.2 运行时要求

| 项 | 客户端 | 服务端 |
|---|---|---|
| Java | 21 | 21 |
| Fabric Loader | ≥ 0.16.x | 与客户端同系 |
| Fabric API | 对应 1.21.1 版本 | 同 |
| GPU/驱动 | Vulkan 1.2+（VulkanMod 路径） | — |

### 2.3 渲染方案（两套备选）

- **方案 A（主推）：VulkanMod**。按用户性能诉求。红线：**直调 OpenGL 的模组会崩溃**，须对照其不兼容清单逐项排查；光影走 Beryl 社区生态，不在 P0 承诺。
- **方案 B（回退/兼容备胎）：Sodium + Iris**。若 VulkanMod 与 SBW/GeckoLib/自研 HUD 实测冲突且无法解决，切回此方案。
- P0 冒烟测试必须覆盖：VulkanMod × SBW × GeckoLib × 自研 HUD 同场共存与 64 人压测帧数。

> 资料来源：Modrinth 用户 Minecraft_GD656（中国开发者，作品均 MIT 许可）。系列 7 个项目、总下载 700 万+，定位"把完整 FPS 体验搬进 MC"。

| 作品 | 功能 | 与本项目的关系 |
|---|---|---|
| **GD656Killicon**（下载最高） | FPS 击杀播报/击杀图标，动效流畅；击杀/助攻/爆头/载具击毁等**计分事件**；BF/CS2/Valorant 多套预设样式 + 自定义样式包；服务端可配加分规则，可同步原生计分板；爆炸 FOV 缩放 | 高参考价值：**击杀事件模型 + BF 样式击杀流**正好是我们 HUD 想做的 |

| **GD656MotionHUD** | 随视角晃动的动态 HUD，"战地味"沉浸感 | HUD 设计借鉴 |
| **GD656FrontVoice** | 阵营战术语音呼叫（装填/投掷/击杀/压制，中英俄语音包） | P3 战场播报的备选方案 |

**取舍结论（双轨策略）：**

1. **不直接入库（现状不允许）**：该系列为 **Forge/NeoForge 优先**。GD656Peek 目前仅 1.20.1 Forge；GD656Killicon 的 1.21.x Fabric/NeoForge 官方口径为"主分支 beta，分支待测试完成后发布"，Fabric 稳定版主要停在 1.20.1。与我们的 **Fabric 1.21.1 + SBW** 底座不匹配。
2. **设计借鉴（写入 HUD 规格）**：breakfront-client 的击杀播报直接参考 Killicon 的**事件模型与 BF 预设动效**；MotionHUD 的动态 HUD 思路；爆炸 FOV 缩放效果；战术语音呼叫留作 P3 播报评估项。
3. **待观察清单**：P0/P1 复查 Killicon/Peek 是否发布 1.21.x Fabric 正式版，发布后逐项评估共存与替换；若整合包未来整体迁至 NeoForge/1.21.4+ 生态，该系列可整套平铺。
4. **Peek 的竞技安全红线**：客户端实体位移 0.5 格在我们的权威服务器上等同"可以穿墙看人"。若要侧头机制，须由 breakfront 服务端验证位移或做纯表现层侧头（不开视野特权），默认不引入第三方客户端位移。
5. 许可 MIT，可引用代码/设计（注明出处）。

## 4. 自研模块 `breakfront` 设计

### 4.1 总体架构

```
┌──────────────────────── 客户端（表现层）────────────────────────┐
│ breakfront-client：部署界面 / 击杀播报 / 比分与进度 HUD /          │
│                   准星与标记 / 波次倒计时 / 伤亡镜头               │
├──────────────────────── 服务端（权威层）────────────────────────┤
│ breakfront（核心，纯服务端逻辑）：                                 │
│ 回合状态机 · 扇区与据点 · 票数/计时 · 波次重生 · 兵种装备发放       │
│ 破坏白名单与回滚 · 击杀归属与计分 · 语音组队辅助 · 反作弊基础      │
├──────────────────────── 数据层（不写代码）───────────────────────┤
│ 地图配置包（每图一个 datapack/JSON）：扇区、据点、重生点、          │
│ 受保护区域、票数、时长 —— 地图作者可加图不加代码                   │
└──────────────────────── 桥接层（关键风险区）─────────────────────┘
│ 击杀/伤害归属桥：SBW 子弹与载具武器 → breakfront 事件               │
└─────────────────────────────────────────────────────────────────┘
```

**原则：一切规则判定在服务端；客户端只做展示与输入。** 服务端/客户端拆两个 Fabric entrypoint 于同一仓库。

### 4.2 回合状态机（服务端骨架）

```
LOBBY(等待/换图) → COUNTDOWN(部署倒计时)
      → BATTLE(攻防进行中：占点/波次/票数)
      → ROUND_END(胜负结算/击杀榜)
      → RESET(战场回滚) → LOBBY(下一局)
```

- 状态迁移由服务端 tick 驱动，单线程权威，无客户端可篡改路径。
- 每状态含进入/退出钩子，支持"局中暂停、管理员指令跳态"（`/bf state <name>` 调试）。

### 4.3 攻防模式（Breakthrough）规则 v0.1

**地图结构**：把战场沿攻方推进方向切成 N 个**扇区 Sector**（建议首图 4 个），每扇区含 1~2 个**目标点**。

**核心规则（参考战地突破，按 32v32 调参）：**

| 规则项 | 设计 | 默认值 |
|---|---|---|
| 攻方目标 | 依序占领全部扇区目标点 | 每点独立计分圈 |
| 攻方复活 | **波次部署**（同波小队齐冲），每死亡-1 部署资源 | 每波间隔 ~10s；总部署资源由地图配置 |
| 守方复活 | 部署于当前扇区后方基地（随扇区失守后撤） | 无限次，但有部署间隔 |
| 攻方推进条件 | 当前扇区全部目标被占 | — |
| 守方获胜 | 攻方部署资源耗尽 或 总时限到 | 总时限建议 20–25 min |
| 攻方获胜 | 推完最后一个扇区并占领 | — |
| 占领判定 | 圈内人数差 > 阈值则涨进度，可被反抢 | 圈半径 ~12–16 格 |
| 载具 | 由部署资源外的**载具点数/刷新点**发放，防一边倒 | 首发图上坦克+直升机各 2 座 |

**Spawn Protection**：重生后 3s 无敌（开火即失效）；**OOB**：守方越入攻方已占扇区纵深受警告/伤害。

**地图配置 JSON 形态（示意）：**
```jsonc
{
  "map": "strike_city", "teams": {"att": {"tickets": 250}, "def": {}},
  "sectors": [
    { "name": "A", "zones": [{"pos": [100, 64, 200], "radius": 14, "id": "A1"}],
      "att_spawn": [[90, 63, 170]], "def_spawn": [[300, 64, 400]] }
  ],
  "protected": [{"from": [0, 0, 0], "to": [600, 120, 600], "except": ["#bf:destroyable"]}],
  "timers": {"match": 1500, "deploy_wave": 10, "spawn_protect": 3}
}
```

### 4.4 兵种与装备（首发 4 兵种）

| 兵种 | 定位 | 主武器倾向（SBW） | 装备 |
|---|---|---|---|
| 突击 Assault | 正面强攻 | 突击步枪 | 榴弹/破片 ×2 |
| 医疗 Medic | 拉人续航 | 步枪 | 医疗包、倒地救援（近身 E） |
| 支援 Support | 压制/反载具 | 轻机枪 | 弹药包、火箭筒 |
| 侦察 Recon | 情报/远射 | 狙击/射手步枪 | 标记弹（命中敌人头上显示标记） |

- 装备发放由 breakfront 在波次部署时**覆盖式发放**到玩家（清空背包，禁止拾取他人枪械落地物）。
- 兵种内可做武器微调：首发用**固定配装**，后续再加选装界面（战地风格"部署前改枪"）。

### 4.5 击杀归属桥（技术风险 ①）

SBW 击杀事件归属没有公开 API 先例，接入策略按顺序尝试：

1. **事件层**：ServerLivingEntityEvents.AFTER_DEATH + DamageSource 追溯攻击者（SBW 若复用 vanilla damage source 即可）。
2. **Mixin 兜底**：若 SBW 子弹/载具武器用自定义伤害类型，mixin 钩其伤害结算类，转发为我们的事件（`KillEvent`/`VehicleDestroyedEvent`）。
3. **启发式降级**：无法归属时不计票（宁缺毋滥，不误扣）。

P1 必须先把这条链路在最小地图上打洞验证（打靶房），它是计分系统的地基。

### 4.6 客户端 HUD/UI（breakfront-client）

- 部署界面：选择兵种 + 选择波次/重生点（渲染为自定义 Screen，不用聊天栏）。
- 常驻 HUD：击杀播报流、扇区进度条、票数/倒计时、占点圈内人数。
- 命中反馈与标记指示（队友/敌人方向标记，可选）。
- **击杀播报交互模型参考 GD656Killicon 的事件与动效设计、MotionHUD 的动态 HUD 思路**（详见 §3.5），自研实现而非直接搬运。
- **渲染纪律：只用 Fabric 标准 GuiGraphics/现代渲染路径，禁止直调 OpenGL**（VulkanMod 红线，见 §2.3）。
- 与 Xaero 小地图等纯 HUD 类模组无冲突风险；与 GeckoLib 实体渲染同屏是否稳定列入冒烟测试。

### 4.7 BF2042 风格全界面与交互规格（矢量绘制，非像素化）

**目标**：客户端所有玩法界面对齐 BF2042 的完整交互逻辑与视觉语言（深色战术风、玻璃拟态卡片、矢量图标、流畅动效），并保证任意 GUI 缩放下边缘清晰、无像素颗粒感。

**界面清单（首发攻防模式需覆盖）**

| 界面 | 内容 | 交互 |
|---|---|---|
| 全屏部署界面（Deploy） | 战场地图 + 兵种/武器/装备卡片 + 载具位 | 兵种切换、部署点选择、波次就绪倒计时 |
| 战术计分板（TAB） | 双方名单、K/D/A、票数/波次剩余 | 按住 TAB 显示 |
| 击杀/得分事件流 | BF 样式击杀图标、助攻、爆头、载具击毁、占点得分 | 自动滚动 |
| 战场 HUD | 据点占领进度条、票数/倒计时、波次提示、当前装备 | 常驻 + 渐隐 |
| 命中反馈 | 命中标记/伤害数字/爆头图标/击杀动效 | 即时 |
| 复活等待界面 | 波次计时 + 观战 + 跳过部署 | 按键跳过 |
| 结算界面 | 胜方/败方、MVP、个人战绩、返回大厅 | 倒计时自动下一局 |
| 地图总览 Overlay | 扇区推进、己方/敌占、载具位置 | 按键开合 |

**矢量绘制口径（"不要像素化"的实现约束）**

1. 界面一律**程序化几何绘制**：圆角矩形/圆/线段/路径多边形/渐变，禁止依赖 16px 位图贴图拉伸；小图标全部矢量路径。
2. 文本用平滑 TrueType 渲染（含中文，如思源黑体等可再分发字体，随包保留许可声明）。
3. 抗锯齿策略：以高分辨率虚拟画布绘制 + 下采样，或等价 AA；目标是 1080p/2K 下无锯齿、缩放平滑。
4. 动效语言统一（淡入/滑入/进度缓动/击杀播报出入场），参考 656 Killicon 的动效质感（§3.5）。
5. **渲染依赖策略（关键）**：首选 breakfront 自研矢量绘制管线（Tessellator 基础图元 + 缓存），保证与 VulkanMod 同屏零冲突；Modern UI（NanoVG）等第三方 UI 库列入待评估，与 VulkanMod 实测冲突则弃用 —— P0 冒烟一票否决。
6. 禁止"贴图化 UI 兜底"，除非性能压力经过实测与评审。

**设计系统（草拟）**：深色半透明底 + 细描边高亮（战术橙/冰蓝双主色）、字号层级 4 档、统一的圆角与间距栅格 —— 先落成一份 UI 设计令牌（token）文档供全界面复用，不与原版背包等 UI 混排。

### 4.8 语音与组队

- Simple Voice Chat 提供近距语音（默认全部 64 人同频道）。
- breakfront 增补：**同小队强制相邻频道** + 部署界面一键拉黑/静音（SVC 现成 API）。

## 6. 破坏与局末回滚（技术风险 ②）

### 6.1 规则

- 破坏对象 = **白名单集合**：命中 `#bf:destroyable` 的方块（建筑外墙、掩体、玻璃等）可被爆炸/武器破坏。
- 受保护：重生点区域、据点核心结构、地面与地形骨架（通过地图配置 `protected` 立方体 + 标签排除）。
- 玩家常规放置/挖掘默认禁止（用权限/方块放置拦截），战场变化只允许"从完整到破坏"单方向。

### 6.2 回滚方案（推荐：差异快照）

1. 竞技场首次装载时，breakfront 扫描配置声明的可破坏区域，记录**每个方块初始状态**到内存表（体积有上限：可破坏集 ≤ 地图总体积 20% 时可行）。
2. 对局中每次方块被破坏 → 记录 `(BlockPos → 原状态)` 变更日志（限制上限，超限自动拒绝进一步破坏并提示）。
3. 局末 RESET 阶段按变更日志逆序还原；还原期间全员在 LOBBY 世界，不可见卡顿。

### 6.3 兜底方案

若区域过大内存吃不消：退化为 **WorldEdit 基准 schematic + 局末整图覆盖还原**（部署倒计时内异步执行，需实测耗时）。

### 6.4 地图工作流（创作侧）

```
WorldEdit 在单机/创作服搭图 → 导出基准（两种格式都备）
  → 首次装载由 breakfront 生成"破坏快照基表"
  → 打包为地图配置包（区域 JSON + schematic）
```
